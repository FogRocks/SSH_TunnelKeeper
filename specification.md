## 1. Назначение

`SSH_TunnelKeeper.bat` — единый файл, который:

- пробрасывает локальные порты компьютера наружу через удалённый SSH-сервер:
  внешние клиенты подключаются к серверу, а сервер перенаправляет трафик
  на локальный компьютер (и наоборот);
- **не требует** белого IP-адреса, проброса портов на роутере или DMZ;
- самостоятельно поддерживает туннель в рабочем состоянии через задачу
  планировщика Windows (старт системы, вход в систему, «сторож» раз в минуту,
  автоперезапуск при сбое без таймаута);
- переживает разрывы соединения: перезапускает `ssh` по циклу с повтором
  через 15 секунд.

Типичные сценарии: доступ к рабочему столу (RDP), сетевым папкам (SMB),
отладчикам, веб-интерфейсам локальных служб.

---

## 2. Глоссарий

| Термин | Значение |
|---|---|
| Reverse tunnel | обратный туннель: сервер слушает удалённый порт, трафик идёт а клиенту |
| RemoteForward (`-R`) | ключ OpenSSH `-R удалённый_порт:localhost:локальный_порт` |
| Проброс (порт) | пара «удалённый_порт : локальный_порт» |
| Задача планировщика | Scheduled Task, объект Windows Task Scheduler |
| EncodedCommand | Base64-кодированный PowerShell-скрипт для `-EncodedCommand` |
| LogonType | тип входа задачи: `Password` (до входа в систему) или `Interactive` |
| BatchMode | режим ssh `BatchMode=yes` — без интерактивного ввода пароля |
| known_hosts | файл с отпечатками ключей SSH-серверов |
| UAC | User Account Control, запрос прав администратора |

## 3. Устройство файла

Файл — «самораспаковывающаяся» связка `bat + PowerShell`. Состоит из двух
частей:

### 3.1. bat-заголовок (строки 1–12, маркер на строке 13)

```
@echo off
chcp 65001 >nul                       # UTF-8 для консоли (кириллица)
set "FINAL_TUNNEL_SELF=%~f0"          # собственный путь -> env-переменная
powershell -NoProfile -ExecutionPolicy Bypass -Command "..."
exit /b
```

- `chcp 65001` — переключение консоли на UTF-8.
- `FINAL_TUNNEL_SELF` — путь к самому файлу передаётся PS-секции
  (PS-секция читает файл и извлекает собственный код).
- Строка `powershell.exe` делает:
  1. собирает маркер **в рантайме** из `[char]95` (символ `_`):
     `__FINAL_TUNNEL_PS_START__`;
  2. читает сам себя как UTF-8 (`[IO.File]::ReadAllText`);
  3. находит единственное вхождение маркера и выполняет код **после** него:
     `[ScriptBlock]::Create(подстрока).Invoke()`.

### 3.2. Ключевой приём с маркером

Маркер в bat-заголовке **не пишется текстом** — он собирается из `[char]95`,
чтобы:

- строка bat-заголовка с реальным подчёркиванием (например путь) не
  совпадала с маркером;
- в файле маркер встречался **ровно один раз** (проверяется тестами),
  а `IndexOf` всегда находил границу между bat и PS-секцией.

### 3.3. PowerShell-секция

Всё, что после маркера (строка 14 и далее) — весь код скрипта: константы,
вспомогательные функции, функции меню и точка входа `Show-Menu`.

## 4. Порядок запуска

| Шаг | Что происходит |
|---|---|
| 1 | bat: `chcp 65001`, `FINAL_TUNNEL_SELF=%~f0` |
| 2 | bat: запускается `powershell.exe` — извлечение и исполнение PS-секции |
| 3 | PS: настройка консоли UTF-8 (kernel32 `SetConsoleOutputCP`/`SetConsoleCP`, `[Console]::Encoding`) |
| 4 | PS: определение путей и констант (см. §10) |
| 5 | PS: проверка прав администратора |
| 6 | `New-Item -Force` для `%USERPROFILE%\.ssh` |
| 7 | `Show-Menu` — бесконечный цикл главного меню |

### 4.1. Проверка прав администратора

Задача планировщика создаётся только админом. Если скрипт запущен без прав:

```
Если не администратор:
  Write-Host "...нужны права администратора"
  Read-Host "...Нажмите Enter — откроется окно с запросом подтверждения (UAC)"
  Start-Process -FilePath $SelfPath -Verb RunAs   # повторный запуск от админа
  exit
```

При двойном клике пользователю показывается окно UAC.

### 4.2. Обработка ошибок на верхнем уровне

Меню обёрнуто в `try/catch` (`Show-Error`): любая ошибка выводится в консоль,
скрипт не «падает» и возвращается в меню.

## 5. Архитектура и функции

Схема потока данных:

```
[Пользователь]
     │  меню (Show-Menu)
     ▼
[Read-Cfg / Save-Cfg]  ───►  %USERPROFILE%\.ssh\ssh_tunnelkeeper_config.txt (Hidden)
     │
     ├── [New-SshKey] ────►  id_ed25519 / id_ed25519.pub (ssh-keygen)
     ├── [Get-PubKeyString] ◄──  публичный ключ из приватного (ssh-keygen -y)
     ├── [Ensure-Connection] ──►  вход в фоне (BatchMode), иначе показать ключ
     ├── [ConvertTo-PortPairs] ─►  "A:B,C:D" -> массив пар
     ├── [Get-TunnelLoopCommand] ─►  PS-цикл туннеля -> Base64
     └── [Register-SshTask] ──►  Scheduled Task "SSH_TunnelKeeper"
                                     │
                                     ▼
                            powershell.exe -EncodedCommand <Base64>
                                     │
                                     ▼
                            ssh -N -R ... (цикл с повтором)
```

### 5.1. Вспомогательные функции

| Функция | Назначение |
|---|---|
| `Pause` | ожидание нажатия Enter |

## 6. Поток авторизации по SSH-ключу

`Ensure-Connection` — центральная функция установки. Поведение:

```
┌─ есть ли приватный ключ id_ed25519?
│
├─ НЕТ ──► создаём ключ (ssh-keygen ed25519, без пароля)
│          показываем публичный ключ (из приватного)
│          ждём любую клавишу (пользователь добавил ключ в authorized_keys)
│          ─► проверяем вход (Test-SshConnection)
│              ├─ успех ──► продолжаем
│              └─ неудача ─► показать ключ, ждать клавишу, повторить
│
└─ ЕСТЬ ─► проверяем вход в фоне (BatchMode=yes, без пароля)
           ├─ успех ──► продолжаем
           └─ неудача ─► показать ключ (его нужно добавить на сервер),
                         ждать клавишу
                         ─► повторная проверка входа
```

Принципиально:

- ключ показывается только в двух случаях: **сразу после создания** или
  **при неудачном входе**;
- каждый показ блокирует выполнение до нажатия клавиши;
- повторная попытка входа происходит после каждого показа.

> Тестовые сценарии (моделирование): «ключа нет», «ключ есть и подошёл»,
> «не подошёл → показан → повтор». Все ветки покрыты.

## 7. Регистрация задачи планировщика

### 7.1. Действие (Action)

Команда туннеля генерируется как **PowerShell-цикл** (`Get-TunnelLoopCommand`)
и передаётся в задачу как **Base64 через `-EncodedCommand`**:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -EncodedCommand <Base64>
```

Такой способ исключает проблемы с кавычками, пробелами и кириллицей внутри
командной строки задачи.

### 7.2. Триггеры

| Триггер | Назначение |
|---|---|
| `AtStartup` + повторение (Repetition) каждую минуту | поднятие туннеля при старте системы и «сторож» |
| `AtLogOn` (для текущего пользователя) + повторение каждую минуту | поднятие при входе и «сторож» |

Повторение задаётся конструкцией:

```
$triggerBoot = New-ScheduledTaskTrigger -AtStartup
$triggerBoot.Repetition = (New-ScheduledTaskTrigger -Once -At (Get-Date)
    -RepetitionInterval (New-TimeSpan -Minutes 1)).Repetition
```

### 7.3. Настройки (Settings)

| Параметр | Значение | Смысл |
|---|---|---|
| `MultipleInstances` | `IgnoreNew` | не плодить копии туннеля |
| `ExecutionTimeLimit` | `[TimeSpan]::Zero` | **без таймаута** (туннель живёт всегда) |
| `StartWhenAvailable` | да | запуск при пропущенном расписании (после сна) |
| `RestartCount` | `999` | автоперезапуск при сбое |
| `RestartInterval` | `1` мин | интервал перезапуска |

`RunLevel = Highest` — задача работает с правами администратора.

### 7.4. Режим входа (LogonType)

Регистрация выполняется `Register-ScheduledTask` со следующими наборами
параметров:

- **С паролем** (запуск **ДО входа** в систему):

  ```
  Register-ScheduledTask -TaskName ... -Action ... -Trigger @(...)
      -User "$env:USERDOMAIN\$env:USERNAME" -Password <пароль>
      -RunLevel Highest -Settings ... -Description ... -Force
  ```

  В этом случае планировщик хранит пароль и LogonType=`Password`.

- **Без пароля** (режим по умолчанию, запуск **при входе**):

  ```
  Register-ScheduledTask -TaskName ... -Action ... -Trigger @(...)
      -User $env:USERNAME
      -RunLevel Highest -Settings ... -Description ... -Force
  ```

  LogonType=`Interactive`.

### 7.5. Почему именно `-User`/`-Password` у `Register-ScheduledTask`

Это результат исправления двойки ошибок:

1. у `New-ScheduledTaskPrincipal` **нет параметра `-Password`** — передача туда
   пароля давала ошибку
   `A parameter cannot be found that matches parameter name 'Password'`;
2. параметры `-Principal` и `-Password` принадлежат **разным наборам**
   (`[Principal]` и `[User]`) и несовместимы друг с другом.

Поэтому пароль и пользователь передаются **напрямую в `Register-ScheduledTask`**
(набор `[User]`): берём рабочую цепочку «`-User` + `-Password` + `-RunLevel`»
без использования `-Principal`.

### 7.6. Копия скрипта в `.ssh`

До регистрации задачи скрипт копирует себя в
`%USERPROFILE%\.ssh\SSH_TunnelKeeper.bat`, поэтому туннель продолжает работать,
даже если установщик удалят или переместят. Копирование не выполняется, если
скрипт уже запущен из этого места (`SelfPath == LivePath`).

## 8. Цикл ввода пароля Windows

Пользователю предлагается ввести пароль Windows (для запуска до входа).
Логика — до **3 попыток**:

```
макс 3 попытки:
  ┌─ ввод пароля (Read-Host -AsSecureString)
  │
  ├─ Enter/пусто ──► режим по умолчанию (запуск ПРИ входе) ──► выход из цикла
  │
  └─ пароль задан ─► пробуем зарегистрировать задачу
       ├─ успех ─► LogonType=Password (запуск ДО входа) ──► выход из цикла
       └─ ошибка ─► "Не получилось создать задачу с этим паролем: <msg>"
                     если попытки остались: "Попробуйте ввести пароль заново..."
                     (повтор, при неудачной последней попытке — выход из цикла)

после цикла:
  если задача ещё не создана с паролем ─► создаём по умолчанию (при входе)
```

Ввод пароля через `Read-Host -AsSecureString` + раскрытие через
`SecureStringToBSTR`/`PtrToStringAuto` с немедленным обнулением
(`ZeroFreeBSTR`).

**Тестовые сценарии:**

| Сценарий | Ожидаемое поведение |
|---|---|
| 3 неверных пароля | 3 вызова с `-Password`, затем 1 вызов по умолчанию (без пароля); без ошибок |
| неверный → верный | 2 вызова: оба с `-Password`, второй с `$env:USERDOMAIN\$env:USERNAME` и верным паролем; вызова по умолчанию нет |
| пустой ввод (Enter) | 1 вызов по умолчанию (без пароля) |

Ввод/попытки регистрируются только через общий код: в коде один путь
регистрации с паролем и один путь по умолчанию (без дублирования).

## 9. Команда туннеля

Генерируется как PowerShell-цикл и инкапсулируется в `-EncodedCommand`.

```
$ErrorActionPreference = 'SilentlyContinue'
while ($true) {
    $ts = Get-Date -Format 'yyyy-MM-dd HH:mm:ss'
    Add-Content -LiteralPath '<log>' -Value "$ts | Проброс [<ports>] -> <user@server> (ssh-порт <port>) ..." -Encoding UTF8
    taskkill /f /im ssh.exe 2>$null
    ssh -N -i "<key>" -p <port>
        -o ServerAliveInterval=15        # keepalive каждые 15 сек
        -o ServerAliveCountMax=6         # через ~90 сек молчания — разрыв
        -o ExitOnForwardFailure=yes      # не жить без успешных пробросов
        -o StrictHostKeyChecking=no      # первый коннект без подтверждения
        -o "UserKnownHostsFile=<kh>"     # отдельный known_hosts
        -NR <удалённый>:localhost:<локальный> ... <user>@<server>
    $ts = Get-Date -Format 'yyyy-MM-dd HH:mm:ss'
    Add-Content -LiteralPath '<log>' -Value "$ts | Соединение потеряно или порт занят — повтор через 15 сек." -Encoding UTF8
    Start-Sleep -Seconds 15
}
```

Построение флага пробросов (несколько портов через запятую):

```
"23389:3389,2445:445"  ==>  "-NR 23389:localhost:3389 -NR 2445:localhost:445"
```

> Кавычки в путях ключа удваиваются; апострофы в пути лога — экранируются.
> Лог ведёт сторожевой цикл, а не основной скрипт.

## 10. Конфигурация

Файл: `%USERPROFILE%\.ssh\ssh_tunnelkeeper_config.txt` (атрибут **Hidden**).

```
server=example.com
user=username
ssh_port=22            (дефолт, если отсутствует)
ports=23389:3389,2445:445
```

- `ports` — список пробросов `"удалённый_порт:локальный_порт"` через запятую
  (пробелы допускаются).
- Запись без BOM; файл скрывается через атрибут `Hidden`.

## 11. Мастер установки (Invoke-Setup)

Последовательность шагов:

1. Ввод адреса сервера (`Get-ServerValue`, валидация символов);
2. Ввод пользователя (`Get-PromptValue`);
3. Ввод SSH-порта (`Get-PortValue`, дефолт 22);
4. Авторизация по ключу (`Ensure-Connection`, §6);
5. Ввод первого проброса портов (`ConvertTo-PortPairs`;
   предлагается RDP `3389`-подобный ввод);
6. Сохранение конфига (`Save-Cfg`);
7. Регистрация задачи (`Register-SshTask`, §7–8);
8. Запуск туннеля.

Каждый шаг выводит понятные сообщения на русском и не теряет уже введённые
значения при повторном входе в мастер (конфиг читается через `Read-Cfg`).

```
 6) Завершить все ssh-туннели
 7) Выход
```

| Пункт | Описание |
|---|---|
| 1 | первичная настройка и создание задачи |
| 2 | удаление: 3 степени — только задача / +настройки / +ключ |
| 3 | состояние задачи, пробросов, ключа, лога; быстрый перезапуск |
| 4 | изменение пробросов, смена сервера (переавторизация), показ/пересоздание ключа |
| 5 | остановка задачи и ssh-процессов |
| 6 | поиск и остановка любых `ssh.exe` (в т.ч. не из этой задачи) и подозрительных задач планировщика |
| 7 | выход |

`Stop-AllSshTunnels` («форензик»): собирает списки

- всех процессов `ssh.exe`;
- процессов, чья командная строка похожа на туннельный запуск;
- задач планировщика, связанных с ssh;

и для каждого списка предлагает выбор «все / номера / ничего».

## 14. Безопасность

- В коде **нет вшитых** паролей, серверов и логинов — всё вводится при установке.
- Конфиг хранится скрытым файлом.
- Пароль Windows **не записывается** в файлы скрипта — его хранит планировщик
  (`LogonType=Password`).
- Приватный ключ не показывается; наружу выводится только публичный
  (получается из приватного через `ssh-keygen -y`).
- Предостережение для пользователя: обратный туннель открывает доступ к машине
  извне — использовать только на своих серверах с корректными ACL и firewall.

## 15. Требования

- Windows 10/11; клиент OpenSSH (`ssh.exe`, `ssh-keygen.exe`) в PATH;
- PowerShell 5+ (модуль `ScheduledTasks`);
- права администратора (UAC) — для создания задачи планировщика;
- на сервере в `sshd_config`:
  - `AllowTcpForwarding yes`
  - `GatewayPorts yes` (для внешних подключений)
  - `ClientAliveInterval 15`
  - `ClientAliveCountMax 6`

## 16. История исправлений

| № | Проблема | Решение |
|---|---|---|
| 1 | Ключ показывался в неудачный момент; возможны опечатки в адресе сервера | Чёткий поток `Ensure-Connection` (создать → показать → проверить; показать только при неудаче); валидация `Get-ServerValue` (защита от `example,com`) |
| 2 | Ошибка `A parameter cannot be found that matches parameter name 'Password'` | Пароль и пользователь передаются напрямую в `Register-ScheduledTask` (набор `[User]`), без `New-ScheduledTaskPrincipal` |
| 3 | Одна неудачная попытка ввода пароля прерывала установку | До 3 попыток ввода; при неудаче — повторный запрос |
| 4 | После 3 неудач установка падала с ошибкой | Задача ставится по умолчанию (запуск при входе) без прерывания установки |
| 5 | `ConvertTo-PortPairs` возвращал `$null` при недопустимом `ports` в конфиге → `@(…)` давал массив из одного `$null`, и `Show-PortPairs` / `Get-TunnelLoopCommand` падали с ошибкой «метод для нулевого значения» | Невалидный формат возвращает **пустой массив**; все вызывающие (`Show-Status`, `Get-TunnelLoopCommand`, `Add/Remove/Set-PortPair`) корректно обрабатывают пустоту |

Оптимизация (без изменения поведения): вынос описания задачи в константу
`$script:TaskDesc`, единый перенос строки в `Register-ScheduledTask`,
сжатие комментариев-истории; устранено дублирование генерации ключа
(`New-SshKey` → цикл на 2 попытки с одинаковой проверкой), убраны лишние
переменные в `Get-TunnelLoopCommand` и лишние присвоения `$plain = $null`,
показ ключа в «Изменить» переиспользует `Show-PubKeyAndWait`.
Поведение подтверждено регрессионным харнесом (22/22 проверок).

## 17. Валидация и тестирование

### 17.1. Автоматические проверки (харнес)

Моделированием вместо реальных команд (`Read-Host`, `Register-ScheduledTask`,
`New-ScheduledTask*`, UAC-блок) проверено — **22/22 `PASS`**:

- **цикл пароля**: 3 неверных → откат к режиму «при входе»; неверный → верный →
  `LogonType=Password`; пустой ввод → режим по умолчанию (12 проверок);
- **`ConvertTo-PortPairs`**: валидная строка, недопустимая, пустая, смешанная;
  `Show-PortPairs` не падает на пустом результате (5 проверок);
- **`Get-TunnelLoopCommand`**: содержит `-NR`, цель, опции ssh, цикл
  `while`, кодируется в Base64 (5 проверок).

Ранее проверялись также `Get-ServerValue` (отклоняет `example,com`,
принимает `example.com`) и ветки `Ensure-Connection` («нет ключа», «есть и
подошёл», «не подошёл → повтор»).

### 17.2. Проверки целостности файла

| Проверка | Ожидание |
|---|---|
| Парсинг PS-секции (`ScriptBlock::Create`) | без ошибок |
| Маркер `__FINAL_TUNNEL_PS_START__` | ровно 1 вхождение |
| Переводы строк | CRLF, без одиночных `LF` |
| BOM | нет (UTF-8 без BOM) |

### 17.3. Что требует ручной проверки

- UAC-элевация при двойном клике;

- реальное ssh-подключение и проброс портов на живом сервере;
- работа «стоража» и автоперезапуска на реальной системе.
