## 1. Назначение

`SSH_TunnelKeeper.bat` — один файл, который:

- пробрасывает локальные порты ПК наружу через удалённый SSH-сервер
  (внешний клиент → сервер → локальный ПК);
- **не требует** белого IP, проброса портов на роутере и DMZ;
- сам держит туннель через задачу планировщика Windows (старт системы, вход,
  «сторож» раз в минуту, перезапуск при сбое без таймаута);
- переживает разрывы: перезапускает `ssh` в цикле с повтором через 15 сек.

Сценарии: RDP, SMB, веб-интерфейсы и отладчики локальных служб.

---

## 2. Глоссарий

| Термин | Значение |
|---|---|
| Reverse tunnel | обратный туннель: сервер слушает порт, трафик идёт к клиенту |
| RemoteForward (`-R`) | `-R удалённый_порт:localhost:локальный_порт` |
| Проброс | пара «удалённый_порт : локальный_порт» |
| Задача планировщика | Scheduled Task (Task Scheduler) |
| EncodedCommand | Base64-скрипт для `powershell -EncodedCommand` |
| LogonType | тип входа задачи: `Password` (до входа) или `Interactive` |
| BatchMode | ssh `BatchMode=yes` — без интерактивного пароля |
| known_hosts | файл отпечатков ключей серверов |
| UAC | запрос прав администратора |

## 3. Устройство файла

Файл — связка `bat + PowerShell`.

**bat-заголовок** (до маркера):

```
@echo off
chcp 65001 >nul                 # UTF-8 в консоли (кириллица)
set "FINAL_TUNNEL_SELF=%~f0"    # путь к файлу -> env-переменная
powershell -NoProfile -ExecutionPolicy Bypass -Command "..."
exit /b
```

PS-команда: собирает маркер **в рантайме** из `[char]95` (`_`), читает файл как
UTF-8, находит маркер и исполняет код после него: `ScriptBlock::Create(...).Invoke()`.

Маркер (`__FINAL_TUNNEL_PS_START__`) не пишется текстом, чтобы встречался в
файле **ровно один раз** (граница bat/PS) и не совпадал с путями.

**PS-секция** (после маркера) — весь код: константы, функции, точка входа `Show-Menu`.

## 4. Порядок запуска

| Шаг | Что происходит |
|---|---|
| 1 | bat: `chcp 65001`, `FINAL_TUNNEL_SELF=%~f0` |
| 2 | bat: старт `powershell.exe`, извлечение и исполнение PS-секции |
| 3 | PS: UTF-8 в консоли (`SetConsoleOutputCP`/`SetConsoleCP`, `[Console]::Encoding`) |
| 4 | PS: пути и константы (§10) |
| 5 | PS: проверка прав администратора |
| 6 | `New-Item -Force` для `%USERPROFILE%\.ssh` |
| 7 | `Show-Menu` — цикл меню |

**Права администратора.** Нужны для задачи планировщика. Без прав: сообщение →
`Start-Process $SelfPath -Verb RunAs` (UAC) → `exit`. При двойном клике
показывается UAC.

**Ошибки.** Меню обёрнуто в `try/catch` (`Show-Error`): ошибка выводится, скрипт
возвращается в меню.

## 5. Архитектура и функции

```
[Пользователь]
     │ меню (Show-Menu)
     ▼
[Read-Cfg / Save-Cfg] ──► %USERPROFILE%\.ssh\ssh_tunnelkeeper_config.txt (Hidden)
     │
     ├─ [New-SshKey] ──────► id_ed25519 / .pub (ssh-keygen)
     ├─ [Get-PubKeyString] ◄─ публичный ключ из .pub или ssh-keygen -y
     ├─ [Ensure-Connection] ► вход в фоне (BatchMode), иначе показать ключ
     ├─ [ConvertTo-PortPairs] ► "A:B,C:D" -> массив пар
     ├─ [Get-TunnelLoopCommand] ► PS-цикл туннеля -> Base64
     └─ [Register-SshTask] ─► задача "SSH_TunnelKeeper"
                                 │
                                 ▼
                        powershell -EncodedCommand <Base64>
                                 │
                                 ▼
                        ssh -N -R ... (цикл с повтором)
```

### 5.1. Вспомогательные

| Функция | Назначение |
|---|---|
| `Pause` | ожидание Enter |
| `Get-PromptValue Label Default` | ввод строки с дефолтом и `Trim()`; пусто = дефолт |
| `Get-PortValue Label Default` | порт 1–65535, цикл до корректного ввода |
| `Get-ServerValue Default` | адрес сервера с валидацией символов (запрет ведущего `-`) |
| `ConvertTo-PortPairs Raw` | `"A:B, C:D"` → `["A:B","C:D"]`; невалидный формат → **пустой массив** (не `$null`, §16) |
| `Show-PortPairs` | вывод списка пробросов |
| `Read-Prompt Prompt` | цветной prompt + `Read-Host` (единая точка ввода; подгоняет высоту окна) |
| `ConvertFrom-Secure Sec` | `SecureString` → открытая строка (единая точка расшифровки паролей/фраз) |
| `Expand-Selection Choices Items` | выбор номеров → элементы (`0` = все, с проверкой границ) |

(защита от argument injection `-oProxyCommand=...`), иначе предупреждение и
повтор ввода (также защита от `example,com`). Та же проверка повторяется при
чтении конфига (`Read-Cfg`) и в `Get-TunnelLoopCommand`.

## 6. Авторизация по ключу

`Ensure-Connection` — центральная функция установки.

```
┌─ есть ключ id_ed25519?
│
├─ НЕТ ─► создаём (ed25519) → показываем публичный ключ → ждём клавишу
│         ─► Test-SshConnection: успех → дальше; неудача → показать, ждать, повтор
│
└─ ЕСТЬ ─► Test-SshConnection (BatchMode, без пароля)
           ├─ успех → дальше
           └─ неудача → показать ключ → ждать клавишу → повторная проверка
```

- Ключ показывается только **сразу после создания** или **при неудачном входе**.
- Каждый показ блокирует до нажатия клавиши; **Esc = отмена** (прерывает установку).
- При неудаче подсказка: если сервер менял ключ — удалить `known_hosts` в `.ssh`
  и повторить.

## 7. Задача планировщика

### 7.1. Действие

Команда туннеля — PS-цикл (`Get-TunnelLoopCommand`), передаётся как Base64:

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -EncodedCommand <Base64>
```

Так нет проблем с кавычками, пробелами и кириллицей.

### 7.2. Триггеры

| Триггер | Назначение |
|---|---|
| `AtStartup` + повтор каждую минуту | старт системы + «сторож» |
| `AtLogOn` (текущий пользователь) | запуск при входе |

### 7.3. Настройки

| Параметр | Значение | Смысл |
|---|---|---|
| `MultipleInstances` | `IgnoreNew` | не плодить копии |
| `ExecutionTimeLimit` | `[TimeSpan]::Zero` | без таймаута |
| `StartWhenAvailable` | да | запуск после пропуска (сон) |
| `RestartCount` | `999` | перезапуск при сбое |
| `RestartInterval` | `1` мин | интервал перезапуска |

`RunLevel = Highest` — с правами администратора.

### 7.4. Режим входа

- **С паролем** (до входа): `Register-ScheduledTask ... -User "$env:USERDOMAIN\$env:USERNAME" -Password <пароль> ...` → LogonType=`Password`.
- **Без пароля** (по умолчанию, при входе): `... -User $env:USERNAME ...` → LogonType=`Interactive`.

Пароль и пользователь передаются **напрямую в `Register-ScheduledTask`** (набор
`[User]`): у `New-ScheduledTaskPrincipal` нет `-Password`, а `-Principal` и
`-Password` — разные несовместимые наборы (иначе ошибка
`A parameter cannot be found ... 'Password'`).

### 7.5. Копия скрипта

Перед регистрацией скрипт копирует себя в `%USERPROFILE%\.ssh\SSH_TunnelKeeper.bat`,
чтобы туннель работал, даже если установщик удалить. Если уже запущен оттуда
(`SelfPath == LivePath`) — копирование пропускается.

## 8. Цикл пароля Windows

Пароль нужен для запуска до входа. До **3 попыток**:

```
макс 3 попытки:
   ├─ Enter/пусто ─► режим по умолчанию (при входе) ─► выход
   └─ пароль задан ─► регистрация
        ├─ успех ─► LogonType=Password (до входа) ─► выход
        └─ ошибка ─► сообщение; повтор, если попытки остались
после цикла: если задачи с паролем нет ─► создаём по умолчанию (при входе)
```

Пароль вводится через `Read-Host -AsSecureString`, раскрывается и немедленно
обнуляется (`SecureStringToBSTR` / `ZeroFreeBSTR`). Путь регистрации один —
без дублирования.

| Сценарий | Поведение |
|---|---|
| 3 неверных | 3 вызова с `-Password`, затем 1 по умолчанию; без ошибок |
| неверный → верный | 2 вызова с `-Password`; вызова по умолчанию нет |
| пустой ввод | 1 вызов по умолчанию |

## 9. Команда туннеля

PS-цикл, инкапсулируется в `-EncodedCommand`. Лог ведёт сам цикл, не скрипт.

```
while ($true) {
    ротация лога > 1 МБ -> .old
    лог: "Проброс [<ports>] -> <user@server> (ssh-порт <port>) ..."
    & "<ssh.exe>"                       # полный путь, запечён при генерации
        -N -i "<key>" -p <port>
        -o ServerAliveInterval=15       # keepalive каждые 15 сек
        -o ServerAliveCountMax=6        # ~90 сек молчания -> разрыв
        -o ExitOnForwardFailure=yes     # не жить без пробросов
        -o "StrictHostKeyChecking=<accept-new|yes>"
        -o "UserKnownHostsFile=<kh>"    # выделенный known_hosts в .ssh
        -NR <удалённый>:localhost:<локальный> ... -- <user>@<server>
    лог: "Соединение потеряно или порт занят — повтор через 15 сек."
    Start-Sleep -Seconds 15
}
```

Построение пробросов: `"23389:3389,2445:445"` → `-NR 23389:localhost:3389 -NR 2445:localhost:445`.

> Отличия от v1.0: убран `taskkill /f /im ssh.exe` (убивал чужие сессии — свои
> завершает `Stop-OwnSshProcesses`); все значения запекаются в команду, цикл не
> зависит от функций основного скрипта.

## 10. Конфигурация

`%USERPROFILE%\.ssh\ssh_tunnelkeeper_config.txt` (атрибут **Hidden**):

```
server=example.com
user=username
ssh_port=22            (дефолт, если отсутствует)
ports=23389:3389,2445:445
```

`ports` — пары «удалённый:локальный» через запятую (пробелы допускаются).
Запись без BOM.

## 12. Меню

```

 2) Удалить               6) Завершить все ssh-туннели
 3) Статус                7) Помощь (настройка сервера)
 4) Изменить              8) Выход
```

| Пункт | Описание |
|---|---|
| 1 | настройка и создание задачи; прошлые значения — как дефолты (ниже) |
| 2 | удаление: 1 только задача / 2 +настройки, лог, копия / 3 +ключ |
| 3 | состояние задачи, пробросов, ключа, лога; перезапуск |
| 4 | пробросы, сервер (переавторизация), показ/пересоздание ключа |
| 5 | `Disable` + `Stop` задачи + стоп ssh туннеля |
| 6 | поиск и остановка любых `ssh.exe` и связанных задач |
| 7 | помощь: готовые команды firewall/sshd для сервера (§15.2) |
| 8 | выход |

### Повторная установка и дефолты

Пункт 1 читает текущий конфиг (`Read-Cfg`) и передаёт его в мастер как дефолты:

```powershell
'1' { $cfg = Read-Cfg; if (-not $cfg['server']) { $cfg = @{} }; Invoke-Setup $cfg }
```

`Invoke-Setup` передаёт `$defaults[...]` в `Get-ServerValue`/`Get-UserValue`/
`Get-PortValue`; `Get-PromptValue` печатает `Удалённый сервер [по умолчанию: <значение>]`,
а Enter возвращает это значение. Итог: при повторной установке поля предзаполнены
прошлыми данными — это **фича** (в самом `.bat` данных нет, §14).

**Сброс к нулю:** удалить `ssh_tunnelkeeper_config.txt` (пункт 2, вариант 2/3 или
вручную). Дефолты не влияют на безопасность — всё проходит те же валидаторы.

## 14. Безопасность

- В коде **нет** вшитых паролей, серверов, логинов.
- Конфиг — скрытый файл; пароль Windows скрипт не пишет (хранит планировщик).
- Приватный ключ не показывается; наружу только публичный.
- Комментарий ключа **нейтральный** (`ssh-tunnelkeeper`) — без имени ПК/пользователя.
- known_hosts туннеля — в `.ssh\ssh_tunnelkeeper_known_hosts` (не `%TEMP%`,
  не глобальный): очистка temp не сбрасывает проверку. Примечание: файл
  расположен в user-writable каталоге — локальный пользователь может его
  изменить; для повышения стойкости храните каталог с ACL только для админа.
- `accept-new`: новый ключ сервера принимается один раз, при смене — отклоняется
  (защита от MITM). При сбое детекта опции — fallback **`yes`** (fail-closed):
  известные хосты проверяются, смена ключа отклоняется; проверка НЕ отключается.
- Ключ с опциональной фразой: по умолчанию без (для автозапуска до входа), с
  фразой безопаснее, но нужен ssh-agent/Pageant.
- `ssh.exe`/`ssh-keygen.exe` — по абсолютным путям (защита от подмены PATH).
- Завершаются только ssh туннеля, чужие сессии не трогаются.
- Обратный туннель открывает доступ к машине извне — только свои серверы с ACL/firewall.

## 15. Требования

- Windows 10/11; клиент OpenSSH (путь разрешается автоматически);
- OpenSSH ≥ 7.6 (для `accept-new`); на старых — fallback `yes` (fail-closed);
- PowerShell 5.1+ (модуль `ScheduledTasks`);
- права администратора (для задачи);
- на сервере `sshd_config`: `AllowTcpForwarding yes`, `GatewayPorts yes`,
  `ClientAliveInterval 15`, `ClientAliveCountMax 6`.

## 15.1. Защита опубликованных портов (периметр)

Скрипт просит у sshd `GatewayPorts yes`, поэтому проброшенные порты
(например `23389`) слушают на всех интерфейсах сервера и видны всему
интернету. Сам скрипт доступ к ним НЕ ограничивает — это настройка сервера.

Рекомендация: разрешить вход только с доверенных IP, остальное запретить.

Linux-сервер (пример):

    # ufw (Ubuntu/Debian)
    sudo ufw allow from 203.0.113.7 to any port 23389 proto tcp
    sudo ufw deny 23389/tcp

    # iptables
    sudo iptables -A INPUT -p tcp --dport 23389 -s 203.0.113.7 -j ACCEPT
    sudo iptables -A INPUT -p tcp --dport 23389 -j DROP
    # сохранить после перезагрузки: netfilter-persistent save

Windows-сервер (пример):

    New-NetFirewallRule -DisplayName "Reverse tunnel 23389" -Direction Inbound `
      -Protocol TCP -LocalPort 23389 -RemoteAddress 203.0.113.7 -Action Allow

Дополнительно (на сервере):
- `GatewayPorts clientspecified` — публиковать порты только на выбранном
  адресе, а не на всех интерфейсах;
- в `sshd_config` ограничить пользователей (`AllowUsers`) и адрес прослушки.

Важно: это защита сервера, а не клиента. Firewall на ПК клиента на эти
порты не влияет — слушает сервер.

### 15.2. Помощь (пункт меню 7)

Скрипт **не настраивает сервер** — он только показывает готовые команды для
копирования на сервер (в консоли, без сохранения в файл).

Подменю: `1` firewall / `2` sshd / `3` всё / `4` Windows (редко) / `0` назад.

- **Firewall** — по каждому удалённому порту отдельный блок (ufw / iptables /
  Windows), с подставленным портом из конфига. Если пробросов нет —
  плейсхолдер `<PORT>`.
- **IP для доступа** — определяется автоматически через `api.ipify.org`
  (`Get-PublicIp`, при неудаче — ручной ввод), вручную или плейсхолдер
  `<ваш_IP>`. При автоопределении предупреждение: за VPN указывайте адрес, с
  которого реально подключаетесь.
- **sshd** — `GatewayPorts yes` (публикация портов на сервере).
- **Чувствительные порты** (`$script:SensitivePorts`: 3389, 445, 1433, …) —
  мягкое предупреждение в меню помощи и после установки (без паники).
- После установки мастер предлагает открыть помощь (`Show-Help`).

Команды firewall ограничивают **источник** (откуда можно подключаться);
`GatewayPorts clientspecified` (bind-адрес) — отдельная тема, не в этом пакете.

## 17. Тестирование

**Харнес** (моделирование вместо реальных команд): v1.0 — **22/22 PASS**,
v1.1 — ~70 проверок PASS, v1.2 — рефакторинг + проверка хелперов PASS. Покрытие:

- валидация портов (`[long]`, диапазон), сервера, пользователя;
- `Get-TunnelLoopCommand`: запечённые пути, `accept-new`, нет `taskkill`,
  ротация лога, парсинг сгенерированного скрипта;
- `Stop-Tunnel`/`Start-TunnelTask`: порядок Disable/Stop/Enable/Start;
- `Stop-OwnSshProcesses`: признаки командной строки;
- Esc в `Show-PubKeyBox -Cancelable` / `Ensure-Connection`;
- цикл пароля (неверные → режим при входе; пустой → дефолт);
- `ConvertTo-PortPairs`: валидная/недопустимая/пустая строка.

**Целостность файла:**

| Проверка | Ожидание |
|---|---|
| Парсинг PS-секции (`ScriptBlock::Create`) | без ошибок |
| Маркер `__FINAL_TUNNEL_PS_START__` | ровно 1 |
| Переводы строк | CRLF, без одиночных `LF` |
| BOM | нет |

**Ручная проверка:** UAC, регистрация задачи с реальным паролем, реальное
ssh-подключение и проброс, работа «стоража» на живой системе.
