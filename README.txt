SSH TunnelKeeper
================

Что это
-------
Один файл SSH_TunnelKeeper.bat. Поднимает обратный SSH-туннель: порты вашего
ПК становятся доступны через удалённый SSH-сервер. Белый IP, проброс портов
на роутере и DMZ не нужны.

Зачем
-----
Доступ к рабочему столу (RDP), сетевым папкам (SMB) и другим локальным
службам из любой точки мира.

Как пользоваться
----------------
1. Запустите SSH_TunnelKeeper.bat (нужны права администратора).
2. Выберите в меню "1) Установить".
3. Укажите сервер, пользователя и SSH-порт. При повторной установке прошлые
   значения подставятся по умолчанию — нажмите Enter, чтобы принять.
4. Если ключа нет, скрипт создаст его и покажет. Добавьте эту строку на
   сервер в ~/.ssh/authorized_keys и нажмите клавишу (Esc — отмена).
5. Скрипт проверит вход по ключу и спросит пробросы
   (удалённый_порт:локальный_порт, несколько через запятую).
6. При желании введите пароль Windows — туннель будет подниматься ещё до
   входа в систему (если пароль не подошёл, задача всё равно ставится и
   работает при входе).

Меню
----
1) Установить                - настройка и создание задачи
2) Удалить                   - 1: только задача / 2: +настройки и лог / 3: +ключ
3) Статус                    - задача, порты, ключ, лог
4) Изменить                  - пробросы, сервер, ключ
5) Остановить туннель        - остановить И отключить задачу
6) Завершить все ssh-туннели - закрыть чужие ssh-процессы и задачи
7) Помощь                    - готовые команды firewall/sshd для сервера
8) Выход

Что делает автоматически
------------------------
- ставит ssh-ключ и входит без пароля;
- создаёт задачу планировщика: автозапуск + контроль каждую минуту +
  перезапуск при сбое (без таймаута);
- держит туннель постоянно (keepalive, повторы), пишет лог (ротация > 1 МБ);
- проверяет ключ сервера (StrictHostKeyChecking=accept-new; при сбое детекта —
  безопасный fallback yes, проверка НЕ отключается);
- хранит настройки в скрытом файле %USERPROFILE%\.ssh\;
- хранит known_hosts туннеля в %USERPROFILE%\.ssh\ssh_tunnelkeeper_known_hosts
  (не во %TEMP%: очистка temp не сбросит проверку ключа сервера);
- при создании ключа предлагает задать парольную фразу (без фразы возможен
  автозапуск до входа; с фразой безопаснее, но нужен ssh-agent/Pageant);
- сохраняет копию себя в %USERPROFILE%\.ssh\ — установщик можно удалить.

Безопасность
------------
- Проверка ключа сервера (защита от MITM): новый ключ принимается один раз
  (accept-new), при смене — отклоняется; fallback безопасный (yes), не "no".
- Ввод пользователя/сервера валидируется как при вводе, так и при чтении
  файла настроек; запрещён ведущий "-"; в ssh-команды добавлен разделитель --
  перед user@host (защита от argument injection).
- ssh/ssh-keygen вызываются по абсолютным путям (защита от подмены PATH).
- Завершаются только ssh-процессы этого туннеля; пункт 6 (завершить все ssh)
  показывает список и требует подтверждения.
- Пароль Windows/парольная фраза не выводятся в сообщения об ошибках.
- Храните каталог %USERPROFILE%\.ssh с правами только для себя: config и
  known_hosts лежат там и влияют на работу задачи.
- Туннель публикует порты НА СЕРВЕРЕ (GatewayPorts). Ограничьте доступ к
  этим портам на самом сервере через firewall: разрешите только ваши IP,
  остальное запретите. Иначе RDP/SMB будут видны всему интернету.
  (Скрипт этого не делает — это настройка сервера.)

Помощь (пункт 7)
----------------
Скрипт не настраивает сервер сам, но по пункту 7 показывает готовые команды
для копирования на сервер:
- firewall (ufw / iptables / Windows) — с подставленными вашими портами;
- sshd (GatewayPorts) — чтобы порты вообще публиковались;
- IP для доступа можно определить автоматически (api.ipify.org), ввести
  вручную или оставить плейсхолдер <ваш_IP>.
Команды показываются в консоли — скопируйте их и выполните на сервере.
Если вы работаете через VPN, укажите адрес, с которого реально подключаетесь.

Примечания
----------
На сервере в sshd_config должны быть разрешены:
AllowTcpForwarding yes, GatewayPorts yes (для внешних подключений).
